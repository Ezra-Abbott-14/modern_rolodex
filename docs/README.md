# Project documentation

This directory is the durable record for the database workstream. Read `decisions.md`
and `architecture.md` before making changes; use `open-questions.md` for unresolved
choices and `testing.md` for evidence. The root `README.md` remains the application
setup and demo guide.

Rules:

- Record only observed facts or decisions stated by the team.
- Mark proposals and unknowns explicitly; do not present plans as implemented.
- Record dates and rationale for meaningful decisions.
- Keep one canonical home for each fact and link instead of duplicating it.
- Never store credentials, real transcripts, recordings, or other personal data here.
- Update docs when implementation or ownership changes invalidate them.
